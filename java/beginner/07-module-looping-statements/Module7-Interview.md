## Module 7: LOOPING STATEMENTS

Q1. When should you use a for loop versus a while loop?
Answer:
Use a for loop when the number of iterations is known in advance, such as iterating over a fixed range, array indices, or counters, because the compact syntax keeps initialization, condition, and update in one place for better readability. The for loop is ideal for situations like "repeat exactly 10 times" or "iterate through array indices 0 to length-1." Use a while loop when the number of iterations depends on runtime conditions, such as reading input until a sentinel value is encountered, processing data until a condition changes, or implementing retry logic where the loop continues until success or maximum attempts. The while loop offers more flexibility when iteration control is complex or spread across multiple statements within the loop body.

Q2. What is the difference between break and continue statements? Provide examples where each is appropriate.
Answer:
The break statement immediately exits the innermost loop or switch statement, transferring control to the first statement after the loop, making it ideal for search operations where you stop once an element is found, error detection where you exit on encountering invalid data, or early termination when a condition is met. The continue statement skips the remaining code in the current iteration and moves to the next iteration, making it useful for skipping invalid data like null or empty strings, filtering elements that don't meet criteria, or avoiding deep nesting by handling special cases early. For example, use break when searching for a specific value and you want to exit immediately upon finding it; use continue when processing a collection but want to skip certain items without stopping the entire loop.

Q3. Explain the limitations of the enhanced for loop. When would you use a traditional for loop instead?
Answer:
The enhanced for loop cannot access the current index during iteration, cannot modify the collection structure (adding or removing elements causes ConcurrentModificationException), provides only read-only access to elements (modifying the loop variable doesn't affect the array), cannot iterate in reverse or skip elements easily, and cannot iterate over multiple collections simultaneously. Use a traditional for loop when you need the index for array manipulation or conditional logic, need to modify array elements in place, want to iterate in reverse, need to iterate with custom step sizes (i += 2), or need to modify the collection during iteration. The enhanced for loop is preferred for simple, read-only forward iteration over all elements where index access isn't needed, offering cleaner syntax and eliminating off-by-one errors.

Q4. What is a ConcurrentModificationException? Why does it occur, and how can you avoid it?
Answer:
ConcurrentModificationException is thrown when a collection's structure is modified during iteration using an iterator or enhanced for loop, triggered by the fail-fast mechanism that detects concurrent modifications to prevent unpredictable behavior. It occurs because the iterator maintains a modification count that's checked on each iteration; if the count changes unexpectedly, it indicates the collection was modified outside the iterator. To avoid it, use the iterator's own remove() method instead of the collection's remove method, use an explicit Iterator and call iterator.remove() for safe removal, use removeIf() method (Java 8+) for predicate-based removal, or collect elements to remove in a separate list and remove them after iteration completes. For concurrent environments, use concurrent collections like CopyOnWriteArrayList that handle concurrent modifications safely.

Q5. What are nested loops? What is their time complexity, and when should you avoid them?
Answer:
Nested loops occur when one loop is placed inside another, causing the inner loop to complete all its iterations for each iteration of the outer loop, with time complexity calculated by multiplying the iterations: two nested loops each running n times yield O(n²) complexity, three nested loops yield O(n³), and so on. Avoid deep nesting (more than three levels) as it dramatically impacts performance and readability; for large datasets, O(n²) operations can be prohibitively slow, and deep nesting makes code hard to understand and maintain. Consider alternatives like hash maps for O(1) lookups to eliminate inner loops, sorting data first to enable more efficient algorithms, extracting inner loops into separate methods for clarity, or using different algorithms with better complexity like using HashSet for membership testing instead of nested loops for search.

Q6. How does the JVM optimize loops? Explain loop unrolling, loop hoisting, and loop fusion.
Answer:
The JIT compiler applies aggressive optimizations to frequently executed loops. Loop unrolling expands the loop body to execute multiple iterations per cycle, reducing branching overhead and enabling better instruction pipelining, often used for small loops with predictable iteration counts. Loop hoisting moves invariant calculations (expressions that produce the same result every iteration) outside the loop to avoid redundant computation, such as moving calculateLimit() before the loop if it doesn't depend on loop variables. Loop fusion combines multiple consecutive loops that iterate over the same range into a single loop to reduce loop control overhead and improve cache locality by processing data in a single pass. These optimizations happen automatically at runtime based on profiling data, making hot loops significantly faster without developer intervention, though writing optimization-friendly code helps.

Q7. What is an infinite loop? Provide examples of both intentional and unintentional infinite loops.
Answer:
An infinite loop is a loop whose condition never becomes false, causing it to execute indefinitely. Intentional infinite loops are common in server applications that continuously accept connections with while(true), game loops that repeatedly process input, update state, and render until exit is requested, and event dispatch threads that process events until shutdown. Unintentional infinite loops are bugs caused by forgetting to update the loop control variable, updating the variable in the wrong direction (decrementing when should increment), writing conditions that can never become false, or floating-point precision issues where a value never reaches the exact target due to rounding errors. Always ensure intentional infinite loops have explicit exit conditions using break, return, or external flags, and be vigilant about loop variable updates to prevent accidental infinite loops.

Q8. What is the difference between while and do-while loops? Provide a real-world scenario where do-while is preferable.
Answer:
The while loop is entry-controlled, checking its condition before executing the loop body, meaning if the condition is initially false, the body never executes. The do-while loop is exit-controlled, checking its condition after executing the loop body, guaranteeing at least one execution regardless of the initial condition. Use do-while for menu-driven programs where you want to display the menu at least once before checking if the user wants to exit, input validation where you prompt for input at least once then repeat if invalid, and game loops where you want to execute one frame before checking if the game should continue. For example, in a menu system, do-while ensures the menu displays even if the user immediately chooses exit, while while might skip the menu entirely if the exit condition is somehow pre-set.

Q9. Explain labeled break and labeled continue statements. When are they useful?
Answer:
Labeled statements allow you to reference a specific loop by name, enabling break or continue to affect outer loops rather than just the innermost loop. Labeled break exits the specified labeled loop entirely, useful when searching in nested structures and you want to exit all loops upon finding the target, while labeled continue skips to the next iteration of the specified labeled loop. These are useful in nested loops for matrix searching where finding an element should exit both loops, graph traversal where certain conditions should skip outer loop iterations, complex control flow where multiple nesting levels require precise flow control, and state machines with nested decision structures. However, excessive use can harm readability; consider refactoring complex nested loops into separate methods with early returns for cleaner code, using labeled statements sparingly only when the alternative would be significantly more complex.

Q10. What happens to loop variables after the loop exits? Explain variable scope in loops.
Answer:
Loop control variables declared in the for loop initialization (like for(int i = 0; i < 10; i++)) exist only within the loop scope and are destroyed when the loop exits, attempting to access them afterward results in a compilation error because they're out of scope. Variables declared before the loop remain accessible after the loop exits, while variables declared inside the loop body are created and destroyed with each iteration. This scoping prevents accidental variable reuse and namespace pollution, improves memory management by destroying variables when no longer needed, and makes code more maintainable by clearly limiting variable lifetimes. If you need a loop variable after the loop, declare it before the loop; otherwise, declare it in the for loop initialization for automatic scope management and cleaner code.

Q11. How would you optimize a loop that creates many objects in each iteration?
Answer:
Creating objects in tight loops causes excessive heap allocation and frequent garbage collection, degrading performance significantly. To optimize, reuse objects by declaring them outside the loop and reinitializing them each iteration instead of creating new ones, use StringBuilder instead of String concatenation which creates new String objects each time, use primitive types instead of wrapper classes to avoid autoboxing overhead, consider object pooling for expensive-to-create objects, use setLength(0) on StringBuilder to clear it rather than creating a new one, or redesign to collect data and create objects in bulk after the loop completes. For example, instead of for(int i=0; i<10000; i++) { StringBuilder sb = new StringBuilder(); } creating 10,000 objects, use StringBuilder sb = new StringBuilder(); for(int i=0; i<10000; i++) { sb.setLength(0); } to reuse one object, dramatically reducing GC pressure and improving performance in production systems.

Q12. What are the best practices for writing clean, efficient loops?
Answer:
Choose the appropriate loop type based on whether iterations are known (for), unknown (while), or require at least one execution (do-while). Use enhanced for loops for simple collection iteration to eliminate index errors and improve readability. Cache collection sizes to avoid repeated method calls in loop conditions. Avoid creating objects in tight loops to reduce GC pressure. Use descriptive variable names for clarity except in trivial cases where i, j, k are conventional. Extract complex loop bodies into separate methods for maintainability. Use continue to reduce nesting and handle special cases early. Document intentional infinite loops explicitly. Use labeled break/continue sparingly, only when alternatives are more complex. Avoid deep nesting beyond three levels by refactoring into methods. Consider Stream API for functional collection operations when appropriate. Ensure all loops have clear termination conditions to prevent infinite loops, and always handle empty collections gracefully to avoid exceptions.
